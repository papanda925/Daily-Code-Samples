## まず試す

1. `docs/demos/gsap-story-cards/index.html`と`app.js`を同じディレクトリに置く。
2. Pythonが使えるならフォルダの親から `python -m http.server 8000` を起動し `http://localhost:8000/` で開く。
3. 発想・制作・公開の三枚を順番にアニメーションする。
4. `SUCCESS` / `RUNNING` / `FAILED` の結果と画面の変化を照合する。現時点では実ブラウザ未検証。

## ここを見る

- [JavaScript本体](../../docs/demos/gsap-story-cards/app.js)
- [HTML画面](../../docs/demos/gsap-story-cards/index.html)
- ポイント：gsap.toは現在の値から目的の値まで変化させるTweenを作ります。gsap.timelineは複数のTweenを順番に管理できます。staggerを指定すれば同じ種類の要素を少しずつずらして表示できます。カード一枚ずつへsetTimeoutを書く方法でも簡単な動きは作れますが、再生・停止・初期状態への復帰を組み合わせると管理が複雑になります。Timelineはその組み合わせを一か所で扱えるため、工程図や短い製品説明に向いています。

## 1か所変えてみる

durationを0.8から1.5へ変更すると、一枚あたりの移動がゆっくりになります。staggerを0.35から0へ変更すれば三枚が同時に現れます。同じカード群でも、時間の組み合わせだけで伝える順番が変わることが分かります。カードそのものの意味はアニメーションの有無によって変わらないようにし、停止した状態でも内容が読めることが設計上の条件です。

## 仕事で使うなら

チュートリアル、サービスの操作説明、進捗の視覚化、教育向けの短い物語の演出に応用できます。金融・医療・重要な意思決定の確認画面では、演出が情報を隠したり操作を妨げたりしないことが大切です。すべてを動かすのではなく、動いたときに学びが増える部分だけを選びます。

## 注意点・失敗しやすい点

アニメーション中に再生ボタンを連打すると、複数の動きが競合することがあります。古いTimelineをkillしてから新しいものを作ることで衝突を減らします。ただし実務ではフォーカス位置や画面読み上げの順序も検証が必要です。外部ライブラリの読み込みに失敗した場合は、カードを静止したHTMLとして表示できるよう初期のマークアップを完成させておきます。

- 外部CDNは初回読み込み時の通信が必要。オフラインでは動作しない。
- 一次情報：[GSAP公式](https://gsap.com/docs/v3/GSAP/)
- 静的構文チェック以外の動作結果は未確認。実際に確認するまで成功例と断定しない。
