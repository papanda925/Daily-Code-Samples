## まず試す

1. `docs/demos/sortablejs-kanban/index.html`と`app.js`を同じディレクトリに置く。
2. Pythonが使えるならフォルダの親から `python -m http.server 8000` を起動し `http://localhost:8000/` で開く。
3. ドラッグまたはボタンでタスクカードを完了に動かす。
4. `SUCCESS` / `RUNNING` / `FAILED` の結果と画面の変化を照合する。現時点では実ブラウザ未検証。

## ここを見る

- [JavaScript本体](../../docs/demos/sortablejs-kanban/app.js)
- [HTML画面](../../docs/demos/sortablejs-kanban/index.html)
- ポイント：Sortable.createを列の要素へ適用すると、列内のカードをドラッグで並べ替えられます。groupで共通グループを指定した二つの列なら、列をまたいだ移動も許容されます。移動後のonEndで各列の子要素数を数え直し、画面の件数へ反映します。ここでは先頭のカードが動いても、もとのカードのテキストや識別子を勝手に書き換えません。複数のカードがある状態で見た目だけを数えるのは学習用として十分ですが、実務では不変のtask IDをカードに持たせる必要があります。

## 1か所変えてみる

実務で使う場合、onEndイベントから「カードID」「移動先の列」「順序」を読み取り、APIへ保存する方式を設計できます。ただしイベント発生直後に成功表示してはいけません。サーバーが保存を拒否した場合は、元の位置へ戻すか、未保存であることを明示する必要があります。ネットワークが切れても移動できるようにするのか、オンラインが必要なのかも要件として決めます。

## 仕事で使うなら

障害対応の進捗管理、原稿の編集ステージ、サンプルのレビュー待ち、軽いチーム作業などに応用できます。監査証跡が必要な業務では、ブラウザのDOMだけでなく、更新者・更新時刻・変更前後をサーバーに記録することが欠かせません。見栄えと業務要件の境界を意識することが、この小さなデモの実務的な学びです。

## 注意点・失敗しやすい点

ドラッグ操作だけではキーボード利用者がタスクを移動できません。サンプルにはボタンの代替を用意し、進捗件数をrole=statusで読み上げ可能にします。実サービスならフォーカス移動、移動対象の選択、取り消し操作も必要です。また、DOMのテキストをそのままタスクIDにする設計は、同名タスクが出た瞬間に曖昧になるので避けてください。

- 外部CDNは初回読み込み時の通信が必要。オフラインでは動作しない。
