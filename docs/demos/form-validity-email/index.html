空欄と形式違いを一つずつ検出する｜フォーム制約検証

メールアドレス欄が空の場合と、書式が違う場合では、直す箇所が違います。

ブラウザーから理由を二つに分けて取得します。

ライブデモへ

最初に知っておく用語

制約検証
入力が条件を満たすかを確かめる機能
形式違い
入力済みの値が要求された形と異なる状態

分岐のフローチャートで考える

ひし形で「空欄」を確認します。

結果によって次に進む先が変わります。

図を読み込み中
Mermaidのソースを見る
flowchart TD
    A["メール欄を確認"] --> B{"空欄？"}
    B -- "はい" --> C["入力が必要と表示"]
    B -- "いいえ" --> D["メール形式を確認"]

ライブデモ

公開データや検証用のファイルで試してください。

空欄と abc と demo@example.test を試す。



実装コード
v=>{const q=field('email');q.required=true;q.value=v;const update=()=>say({空欄:q.validity.valueMissing,形式違い:q.validity.typeMismatch,通過:q.validity.valid});q.oninput=update;update()}


結果の見方
空欄と形式違いが別々の理由として出る。
ブラウザーは形式を見て判断する。
受信先のアドレスが実際に存在するかは、この検証からは分からない。


コードの要点
type=email と required を指定して validity の valueMissing と typeMismatch を見る。


仕事で使うとき
画面で検証していても、受信する側で同じ前提を確認する。
