連続入力で検索処理が何回走るか数える｜Lodash

検索欄に一文字入るたびに検索すると、連続入力中に何度も処理が走ります。

入力に短い間隔を空けると、検索回数がいくつになるか試します。

ライブデモへ

最初に知っておく用語

デバウンス
連続する呼び出しを待って最後の処理をまとめる方式
イベント
入力などの発生通知

ガントチャートで考える

入力のたびに待機をやり直します。

この例では最後の入力から250ms後に検索します。

ライブデモ

公開データや検証用のファイルで試してください。

入力間隔を 0,80,160 にする。

次は 0,400,800 で実行する。



実装コード
async v=>{const {default:debounce}=await lib('lodash@4.17.21/debounce');let hits=0,keys=0;const times=split(v).map(Number);if(times.length>25||times.some(x=>!Number.isFinite(x)||x<0||x>3000))throw Error('0〜3000msを25件以内で指定してください');const search=debounce(()=>say({入力:keys,検索:++hits}),250);await Promise.all(times.map(t=>new Promise(r=>setTimeout(()=>{keys++;search();r()},t))));await new Promise(r=>setTimeout(r,280))}


結果の見方
待機時間が250msなら、前者は1回、後者は3回の検索を見込める。
間隔は各入力の開始時刻をミリ秒で並べる。
0,80,160 では最後の時刻160から待機を数え直す。
バックグラウンドではタイマーが遅れる場合がある。


コードの要点
入力イベントと debounce で包んだ検索処理を別々にカウントする。


仕事で使うとき
待機時間を長くすると検索は減る。
画面に結果が出るまでの遅れも増える。
