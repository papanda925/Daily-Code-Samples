# Excel XLOOKUP：同じ検索キーの最初と最後の一致を比較

元記事：[XLOOKUPで重複した商品コードを探す](https://github.com/papanda925/Blog-Ideas/blob/main/publish/items/20261016-09-body.md)。

XLOOKUPの`search_mode`は「前から検索するか、後ろから検索するか」の指定です。**表の最後の行が業務上の最新レコードとは限らない**点を重視した関数教材です。

## まず試す

XLOOKUPが使えるExcel for Microsoft 365、Excel 2021/2024などで新規シートを作る。次の架空のデータを入力する。

| 行 | A列:商品コード | B列:単価 |
|---|---|---:|
| 2 | P101 | 120 |
| 3 | P102 | 200 |
| 4 | P101 | 150 |

E2にP101を入れ、F2・G2へ`formulas.txt`の二式をコピーする。**期待値（Excel実機未実行）**：F2=120、G2=150。どちらもP101に一致しているが、検索方向の違いで返る行が変わる。

## ここを見る

- `XLOOKUP(E2, 検索範囲, 戻り値範囲, "未登録", 0, 1)`は前から検索する。
- 最後の引数`-1`は後ろから検索する。`0`はキーの完全一致を示す。
- 追加引数の`"未登録"`は見つからない状態を数値0と区別するための表示。
- `search_mode=2/-2`は並び順の前提がある二分探索なので、本教材では使わない。

## 1か所変える

A4のP101をP103へ書き換えると、F2もG2も120になる想定。E2をP999へ変えると両方「未登録」になる。表を並べ替えると「後ろの一致」が変わり得るため、最新の取引日を判定する場合は日付列による別のルールが必要。

## 仕事で使うなら

商品マスタで重複が禁止なら、どちらの一致を選ぶ前に重複を検知する。履歴表で重複が許容される場合も、行順と適用開始日の対応を保証できないなら最新単価の決定には使えない。入力した商品コードの先頭ゼロ、空白、文字列/数値の違いを確認する。
