失敗するテスト入力を最小化する｜fast-check

足し算をすると値が増えると思うと、負の入力を見落とします。

実験で失敗する入力を探し、どの値が仮定を崩したかを調べます。

ライブデモへ

最初に知っておく用語

反例
仮定が成り立たない入力
縮小
失敗を保ったまま入力を小さくする処理

分岐のフローチャートで考える

ひし形で「仮定は成り立つ」を確認します。

結果によって次に進む先が変わります。

ライブデモ

公開データや検証用のファイルで試してください。

シード42で試す。

43に変えて反例を見る。



実装コード
async v=>{const f=await lib('fast-check@4.0.0');const c=f.check(f.property(f.integer({min:-1000,max:1000}),f.integer({min:-1000,max:1000}),(a,b)=>a+b>=a),{seed:Number(v)||42,numRuns:100});say({失敗:c.failed,反例:c.counterexample,縮小回数:c.numShrinks,seed:c.seed,path:c.counterexamplePath})}


結果の見方
負の b を含む小さな反例が得られる。
例で調べる仮定は a+b が a 以上というもの。
b の符号に注目すると、失敗した理由を短く説明できる。


コードの要点
整数の生成器を二つ用意し、fc.property で仮定を検査する。


仕事で使うとき
失敗報告にはシードとパスを残す。
後から同じ反例を再現しやすい。
