## まず試す

1. `docs/demos/tonejs-four-notes/index.html`と`app.js`を同じディレクトリに置く。
2. Pythonが使えるならフォルダの親から `python -m http.server 8000` を起動し `http://localhost:8000/` で開く。
3. 4音のメロディーを再生しテンポを変更する。
4. `SUCCESS` / `RUNNING` / `FAILED` の結果と画面の変化を照合する。現時点では実ブラウザ未検証。

## ここを見る

- [JavaScript本体](../../docs/demos/tonejs-four-notes/app.js)
- [HTML画面](../../docs/demos/tonejs-four-notes/index.html)
- ポイント：ブラウザはユーザーが操作していない段階で音が鳴ることを制限しています。Tone.start()はクリックなどのユーザー操作に結び付けて呼ぶ必要があります。音源はTone.Synthで作り、toDestinationによってスピーカー側の出力経路に接続します。triggerAttackReleaseで音名、長さ、開始時刻を指定します。JavaScriptのsetTimeoutで一つずつ鳴らす方式より、AudioContextの時刻を使って演奏を予約する方が音のタイミングを設計しやすくなります。

## 1か所変えてみる

音の並びをC4、E4、G4、C5から、C4、F4、G4、B4へ変えれば響きが変わります。周波数を数値で書くこともできますが、最初は音名を使った方が読みやすいでしょう。音の長さを変更すると、隣の音と重なることがあります。そのため再生予約の時間間隔と一音の長さは別々に考えます。連続再生へ拡張するなら、停止・再開・速度変更時の予約済み音の扱いが重要になります。

## 仕事で使うなら

タイピング教材のフィードバック、ゲームの効果音、タイミング学習、音程の可視化などへ応用できます。ただし通知音の鳴動は端末の状態に依存し、重要な警告を音だけに頼ってはいけません。業務システムでは画面テキスト・通知履歴・音を組み合わせた設計が必要です。

## 注意点・失敗しやすい点

再生ボタンを何回も押すと音が重なります。楽器をそのたびに新規作成し続けるのではなく、サンプルでは基本的に音源を再利用します。停止時にはdisposeして後始末しますが、予約済み音との関係は実ブラウザで追加確認が必要です。イベント会場で公開する場合は自動再生しないこと、音声を止める操作をいつでも使えること、聴覚に配慮した代替の視覚情報を併記することが大切です。
