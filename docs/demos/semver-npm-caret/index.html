npmの「^1.2.3」はどこまで更新できる？ 0.xとの違いをsemverで試す

npmの依存関係に ^ が付いていると、更新できる版には範囲があります。

先頭が0の場合は範囲が狭くなります。

ライブデモへ

最初に知っておく用語

キャレット
互換性を想定して更新範囲を指定する記号
プレリリース
正式公開前の版

状態遷移図で考える

キャレットが ^0.2.3 の場合です。

候補ごとに判定先をたどります。

図を読み込み中

ライブデモ

公開データや検証用のファイルで試してください。

^0.2.3 を入力する。

0.2.9 と 0.3.0 を比べる。



実装コード
async v=>{const {default:s}=await lib('semver@7.8.5');if(!s.validRange(v))throw Error('範囲指定を確認してください');say(Object.fromEntries(['0.0.3','0.0.4','0.2.3','0.2.9','0.3.0','1.2.3','1.2.9','1.3.0-beta.1','1.3.0','1.9.0','2.0.0'].map(n=>[n,s.satisfies(n,v)?'範囲内':'範囲外'])))}


結果の見方
0.2.9 は範囲内。
0.3.0 は範囲外。
^1.2.3 と ~1.2.3 を比べると、1.3.0 の扱いが違う。
^0.0.3 では 0.0.4 も範囲外になる。
安定版が入る範囲でも、1.3.0-beta.1 は既定で外れる場合がある。


コードの要点
semver.validRange で指定を検証します。
semver.satisfies で候補ごとに範囲を判定します。


仕事で使うとき
更新作業では npm ls で実際の版を確かめる。
範囲の指定だけでは、導入済みの版は分からない。
