## まず試す

1. `docs/demos/qrcodejs-event-invite/index.html`と`app.js`を同じディレクトリに置く。
2. Pythonが使えるならフォルダの親から `python -m http.server 8000` を起動し `http://localhost:8000/` で開く。
3. 架空イベント名をQRコードへ変換する。
4. `SUCCESS` / `RUNNING` / `FAILED` の結果と画面の変化を照合する。現時点では実ブラウザ未検証。

## ここを見る

- [JavaScript本体](../../docs/demos/qrcodejs-event-invite/app.js)
- [HTML画面](../../docs/demos/qrcodejs-event-invite/index.html)
- ポイント：QRCodeコンストラクターに表示先のDOM要素とテキスト、縦横のサイズ、誤り訂正レベルなどを渡します。ライブラリは文字列をQRコードのパターンへ変換し、canvasまたはHTML要素として描画します。入力を変えるたびにQRCodeのインスタンスを増やし続けると、前の画像が残ったり画面が肥大化する可能性があります。デモでは既存インスタンスを保持し、clearとmakeCodeで書き換えます。文字列が変わるとパターンも変わりますが、見た目だけで中身は読み取れません。

## 1か所変えてみる

QRに長い文章を詰め込むと模様が細かくなり、印刷したときに読み取りにくくなることがあります。案内先のURLを埋め込む場合はドメイン・HTTPS・有効期限を事前に確認します。QRコードからアクセスする先のサイトが変更された場合、静的に印刷したQRの内容は変わりません。頻繁に変わる案内は、変更可能なランディングページを設ける方が運用しやすい場合があります。

## 仕事で使うなら

案内カード、展示の解説ページ、機器の公開マニュアルへのリンクなどに使えます。社内の業務手順へ応用する場合は、誰がURLを変更できるか、印刷物の回収をどう行うか、失効させたいときにどうするかまで設計してください。コード生成そのものは簡単でも、リンクの寿命管理が重要です。

## 注意点・失敗しやすい点

QRコードは暗号化や認証ではありません。読み取れば文字列が見えるため、パスワード、秘密トークン、個人識別情報、非公開の会議URLなどを安易に入れないことが重要です。また、QRコード自体に悪意がなくても、読み取ったユーザーを偽サイトへ誘導することがあります。掲載するドメインを目で確認できるよう平文表示し、運用時は定期的なリンク検査を考えます。

- 外部CDNは初回読み込み時の通信が必要。オフラインでは動作しない。
