集計中も画面のボタンを操作できるようにする｜Web Workers

大きな集計を画面と同じ場所で実行すると、ボタンの反応が後回しになります。

同じ計算を別の実行場所へ移して比べます。

ライブデモへ

最初に知っておく用語

メインスレッド
画面描画や入力を扱う実行場所
Worker
別の場所で処理を実行する仕組み

シーケンス図で考える

計算の応答を待つ間に、画面が別の操作を受け付ける例です。

図を読み込み中
Mermaidのソースを見る
sequenceDiagram
    participant U as 利用者
    participant P as 画面
    participant W as Worker
    U->>P: 集計する
    P->>W: 計算を依頼
    U->>P: 別のボタンを押す
    P-->>U: ボタンの結果を表示
    W-->>P: 集計結果を返す

ライブデモ

公開データや検証用のファイルで試してください。

メインとWorkerで順に集計する。

集計中に加算ボタンを押す。



実装コード
()=>{const work=()=>{const end=performance.now()+420;let n=0;while(performance.now()<end)n++;return n};let count=0,w,url;const stats=panel('p');button('加算',()=>stats.textContent='ボタンを押した回数 '+(++count));button('メインで集計',()=>say({集計回数:work()}));button('Workerで集計',()=>{w?.terminate();if(url)URL.revokeObjectURL(url);url=URL.createObjectURL(new Blob(['onmessage=()=>postMessage(('+work.toString()+')())'],{type:'text/javascript'}));w=new Worker(url);w.onmessage=e=>say({集計回数:e.data});w.postMessage('start');say('Workerで集計中')});cleanup=()=>{w?.terminate();if(url)URL.revokeObjectURL(url)}}


結果の見方
Workerを使う回では加算ボタンが応答しやすい。
同じ計算を二つの場所で実行する。
調べたいのは計算中のボタンの反応だ。
集計数の大小だけで方式の優劣は決めない。


コードの要点
一方を通常の関数、もう一方をWorkerで実行し、postMessageで結果を受け取る。


仕事で使うとき
処理が小さいとWorker起動やデータ転送の負荷が相対的に大きくなる。
