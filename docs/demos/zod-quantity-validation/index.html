申請JSONのどの項目が不正か表示する｜Zod

入力欄に同じ2が見えても、文字列と数値では型が違います。

Zodで数量を検査し、利用者に示すエラーの位置を取り出します。

ライブデモへ

最初に知っておく用語

スキーマ
入力の形と制約を定めたルール
パス
誤りが起きた項目の位置

分岐のフローチャートで考える

ひし形で「quantity の型は整数」を確認します。

結果によって次に進む先が変わります。

図を読み込み中
Mermaidのソースを見る

ライブデモ

公開データや検証用のファイルで試してください。

数量を文字列のまま実行する。

引用符を外して実行する。



実装コード
async v=>{const {z}=await lib('zod@4.6.7');const r=z.object({quantity:z.number().int()}).safeParse(JSON.parse(v));say(r.success?r.data:r.error.issues.map(x=>({位置:x.path.join('.'),理由:x.message})))}


結果の見方
文字列では quantity がエラーになる。
数値の 2 は通る。
引用符を外すと値の見た目は同じでも型が変わる。
入力画面で数量を数値として送る設計なら、負数と小数も別のテストにする。


コードの要点
z.number().int() を含むオブジェクトを safeParse し、失敗時に issue の path を表示する。


仕事で使うとき
APIが受け取る型を操作画面の担当者と共有する。
型変換を行うならその前後を別にテストする。
