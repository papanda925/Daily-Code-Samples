## まず試す

1. `docs/demos/fusejs-book-search/index.html`と`app.js`を同じディレクトリに置く。
2. Pythonが使えるならフォルダの親から `python -m http.server 8000` を起動し `http://localhost:8000/` で開く。
3. 本のタイトルを検索し、近い候補の順位を見る。
4. `SUCCESS` / `RUNNING` / `FAILED` の結果と画面の変化を照合する。現時点では実ブラウザ未検証。

## ここを見る

- [JavaScript本体](../../docs/demos/fusejs-book-search/app.js)
- [HTML画面](../../docs/demos/fusejs-book-search/index.html)
- ポイント：Fuseへ渡す配列は検索対象、keysは照合するフィールドです。thresholdはあいまい一致の許容度を調整する値で、0に近いほど厳しくなります。includeScoreで取得するscoreは、検索結果の一致度を示す内部的な評価値ですが、ビジネス上の「95%正しい」といった確率ではありません。曖昧な検索で上位に出たものを、そのまま正解として自動確定するのは危険です。表示上はユーザーが候補の文字列を確認できるようにします。

## 1か所変えてみる

keysへ著者名やジャンルを追加すると検索対象が増えますが、同じ文字列でもタイトルに一致したものを優先したい場合は重み付けを考えます。たとえば「Web」という語がタイトルにもジャンルにもある場合、どちらを強く評価するかは業務の目的によります。小さな誤字の許容を優先すると無関係な候補も増えるため、検索の再現率と精度の両方を意識してください。

## 仕事で使うなら

社内用語集、部品名の候補表示、イベント名検索、FAQナビゲーションなどに使えます。ただし医薬品名や決済相手の選択など、誤選択の影響が大きい用途は候補表示と確定操作を分け、正式な識別子による照合が必要です。検索を便利にしても、識別や承認の責任を検索ライブラリへ任せないことが重要です。

## 注意点・失敗しやすい点

日本語の全角半角、カタカナとひらがな、漢字の読み、濁音と清音は、単純なあいまい一致だけでは吸収しきれません。必要ならデータ側へ読み仮名や別名を持たせ、正規化したフィールドを別途用意します。さらに検索対象が数十万件へ増えると、全データをブラウザへ渡す方式が重くなり、権限のない人へ情報を渡してしまう危険もあります。サーバー検索へ切り替える境界を決めてください。
