設定ファイルのインデントで構造が変わる理由｜yaml

YAMLでは、キーの手前の空白が親子関係を決めます。

一行の空白を消し、同じ名前がどこへ移るかを見ます。

ライブデモへ

最初に知っておく用語

YAML
設定を階層で書けるテキスト形式
インデント
行頭の空白で示す階層

マインドマップで考える

中央から左右のケースを読みます。

port の先頭に空白を付けると所属先が変わります。

図を読み込み中
Mermaidのソースを見る
mindmap
    root((設定の階層))
      インデントあり
        server の中に port
      インデントなし
        server と port が同じ階層

ライブデモ

公開データや検証用のファイルで試してください。

port の先頭を2空白にする。

次に空白を消す。



実装コード
async v=>{const {parseDocument}=await lib('yaml@2.7.0');const y=parseDocument(v);say(y.errors.length?y.errors.map(x=>x.message):y.toJS())}


結果の見方
同じキーが別の階層に移る。
空白を消すと server の値が空になり、port が同じ階層に移る。
エラーがない場合でも設定の意味が変わる点が重要だ。


コードの要点
parseDocument の結果をJSON表示し、errors があれば位置を確認する。


仕事で使うとき
設定変更は整形後だけでなく、変換した構造でもレビューする。
