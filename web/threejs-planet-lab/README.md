## まず試す

1. `docs/demos/threejs-planet-lab/index.html`と`app.js`を同じディレクトリに置く。
2. Pythonが使えるならフォルダの親から `python -m http.server 8000` を起動し `http://localhost:8000/` で開く。
3. 球体の回転速度をスライダーで変える。
4. `SUCCESS` / `RUNNING` / `FAILED` の結果と画面の変化を照合する。現時点では実ブラウザ未検証。

## ここを見る

- [JavaScript本体](../../docs/demos/threejs-planet-lab/app.js)
- [HTML画面](../../docs/demos/threejs-planet-lab/index.html)
- ポイント：シーンは3D空間の登場人物をまとめる入れ物、カメラは観察者の位置、メッシュは形状と表面の材質の組み合わせです。SphereGeometryは頂点から球体を構成し、MeshStandardMaterialは照明に反応する見え方を決めます。物体をsceneへ追加しただけでは画面は更新されません。renderer.renderでカメラから見た結果をcanvasへ描画します。回転の角度を単に毎フレーム固定量だけ加算すると、PCの描画速度によって回転の速さが変わります。そこで前回フレームからの経過秒を用いる設計にします。

## 1か所変えてみる

球の材質をwireframe=trueからfalseへ変更すると輪郭線中心の表示が面の塗りつぶしへ変わります。三角形の網目が分かりやすいのは前者ですが、表面の質感を見せるなら後者が向きます。近くにライトを置く位置を変更すると、陰影がどこに現れるかも変わります。一方、ライトを追加しても球体の3D座標が動くわけではありません。この「モデルの位置」「材質」「光」「カメラ」が独立している点を区別することが、複雑な3Dアプリのデバッグにもつながります。

## 仕事で使うなら

機器の形状確認、展示、製品の回転プレビュー、立体配置の教材に応用できます。正式な設計図や寸法保証の代用にする場合は、縮尺、単位、カメラ投影、色管理、端末別の描画品質を別途検証しなければなりません。資料作成では「触れると理解が増す情報」だけを3Dにし、単純な表や説明はHTMLで残す方が読み上げ・印刷・検索に適します。

## 注意点・失敗しやすい点

WebGLが無効な環境、端末のメモリが少ない環境、企業ネットワークでCDNを許可していない環境では動かない場合があります。またウィンドウを小さくしたときにcanvasだけ縮めてもカメラのアスペクト比が古ければ見た目が変形します。実用版ではresize処理と画素密度の上限を用意してください。大量に新しいGeometryやMaterialを作り続けるとGPU側の資源を消費するため、不要になったらdisposeすることも重要です。

- 外部CDNは初回読み込み時の通信が必要。オフラインでは動作しない。
