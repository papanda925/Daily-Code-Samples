外部連携の入力仕様をJSON Schemaで共有する｜Ajv

別のチームから届くJSONに必要な項目がないと、取り込み処理が止まります。

必須項目の不足と型違いを区別して返します。

ライブデモへ

最初に知っておく用語

JSON Schema
JSONの構造や制約を表す仕様
必須項目
入力から省けない項目

要求図で考える

連携の条件を一つの要求として表します。

入力データの id が必須で、整数であることを確認します。

図を読み込み中
Mermaidのソースを見る
requirementDiagram
    requirement ExternalRecord {
        id: R1
        text: id is present and integer
        risk: medium
        verifymethod: test
    }
    element InputValidator {
        type: Ajv
    }
    InputValidator - satisfies -> ExternalRecord

ライブデモ

公開データや検証用のファイルで試してください。

空のオブジェクトで実行する。

id を文字列と整数で試す。



実装コード
async v=>{const {default:A}=await lib('ajv@8.17.1');const f=new A({allErrors:true}).compile({type:'object',required:['id'],properties:{id:{type:'integer'}}});say(f(JSON.parse(v))?'検証に合格':f.errors)}


結果の見方
必須エラーと型エラーの違いが見える。
スキーマを共有すると、連携先も同じ条件を検証できる。
id を追加しても、文字列のままなら型の条件で止まる。


コードの要点
スキーマを compile し、検証関数と errors を使う。


仕事で使うとき
エラーの位置を通知すると、連携先が修正しやすい。
